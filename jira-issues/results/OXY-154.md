## Expanded Description

**What this task likely is:** Provide a single importable, reusable helper that makes Oxygen's color theme ergonomic — both the **bootstrap** (`PageApp.prePageLoad` wiring for `ColorMode` + `Theme` pack) and the **UI** (mode toggle + pack picker) — so apps and showcase pages stop copy-pasting the same 4-line `prePageLoad` and 3-button `Button("Light/Dark/System")` / 40-line `ThemePage` `foreach(OxygenThemes.all)` picker.

**Current state (verified from code):**

- Theme pack **definitions** live in `style.OxygenThemes` (`modules/ui/web/src/main/scala/oxygen/ui/web/style/OxygenThemes.scala:1-250`) — 10 packs (Graphite core + 5 Graphite colorways + Aurora/Ember/Violet/Ocean), each `Pack(id,name,blurb,dark:Seeds,light:Seeds)`, `storageKey = "oxygen.theme-pack"`, `default = graphite`, `all`, `byId`, `parse`.
- Runtime **apply/persist** lives in `service.Theme` (`modules/ui/web/src/main/scala/oxygen/ui/web/service/Theme.scala:1-70`) — `applyPack(pack)` injects two `<style>` blocks (`:root,[data-color-mode="dark"]` + `[data-color-mode="light"]` via `OxygenStyleVars.toCSS`), `data-oxygen-theme` attribute, `localStorage` read/write, `Broadcast.postThemePack` + `subscribeCrossTab`. No `install` helper; callers must sequence it manually.
- Light/dark/system **mode** lives in `service.ColorMode` (`modules/ui/web/src/main/scala/oxygen/ui/web/service/ColorMode.scala:1-90`) — `Mode.{System,Light,Dark}`, `applyMode`, `applyStoredOrSystem`, `setAndPersist`, `prefersDark` via `MatchMedia`, `data-color-mode` attribute, own `storageKey = "oxygen.color-mode"`, separate `Broadcast` channel (`oxygen.color-mode`). Theme pack and mode are **two independent services with two storage keys, two attributes, two channels** — there is no unified `ColorTheme` facade.
- Color system generation: `style.OxygenColorSystem` (`modules/ui/web/src/main/scala/oxygen/ui/web/style/OxygenColorSystem.scala:1-538`) `Seeds -> GeneratedPalette -> OxygenStyleVars[String]` via `generate` + `toStyleVars`; defaults in `defaults.OxygenStyleVarDefaults` (`OxygenStyleVarDefaults.scala:1-30`) expose `Oxygen` / `OxygenLight` + `oxygenColorSheets`. `create.OxygenStyleVars` (`create/OxygenStyleVars.scala:1-400`) defines the `CSSVar` surface (`color.primary/ fg/ bg/ highlight/ status/ brand`, `spacing`, etc.) and `toCSS`.
- App bootstrap is **manual** everywhere: canonical snippet in `docs/docs/ui/builders.md:187-196` and `docs/docs/ui/index.md` is `override def prePageLoad = ColorMode.applyStoredOrSystem *> Theme.applyStoredOrDefault *> ColorMode.subscribeCrossTab *> Theme.subscribeCrossTab`. Copied verbatim in `example/apps/ui/src/main/scala/oxygen/example/ui/UIMain.scala` (same 4 lines) — no `Theme.install()` or `ColorTheme.install` helper.
- Picker UI is **duplicated, not reusable**:
  - `defaults.StylesPage` (`defaults/StylesPage.scala:60-68`) `colorModeToggle` = 3 bare `Button("Light/Dark/System").small.subtle` with `onClick := ColorMode.setAndPersist(...)`.
  - `example/.../page/showcase/pages/ThemePage.scala:20-115` = full theme studio: mode row (same 3 buttons) + `OxygenThemes.all.foreach` with `themeSwatch` + per-pack `Button` that does `Theme.applyAndPersist(pack) *> state.update *> PageMessages.schedule(...)`, ~90 lines, not reusable.
  - `example/.../page/showcase/pages/ShellPage.scala` and `KitchenSinkPage.scala` repeat the 3-button mode toggle. `example/.../page/showcase/pages/FormColorPage.scala` is unrelated (color field picker for hex, not theme).
- Helpers that partially exist: `create.CSSColor` (`create/CSSColor.scala:1-200`) with `darken/lighten/mix/setOpacity`, `create.ColorTransform` (`create/ColorTransform.scala:1-60`), `style.Contrast` (`style/Contrast.scala:1-120`) for WCAG checks, `style.Breakpoints`/`create.MediaCSS` — none wrap theme bootstrap or picker.
- Grep for `helper.*color|helper.*theme|reusable helper|ColorHelper|ThemeHelper` across `modules/ui` returns only `htmlAttrs.scala:55` TODO `add color helpers here` for `svgStroke` (unrelated SVG attr, not theme). No `TODO(OXY-154)` marker, no skipped test, no design doc for this helper was found.
- `oxygen-ui-web` package map (`docs/docs/ui/builders.md:82-90`, `agent-guide.md`): `style` = definitions, `service` = runtime apply, `create` = primitives, `component` = chrome controls, `defaults` = `coreOxygenStyleSheets` + default pages. The helper could live in any of the three consistent homes — most naturally `service` (combined install) + `component` (picker widget), or a single `helper` module.

**Why it matters (Priority Normal):** Without the helper every Oxygen app pays a copy-paste tax and risks drift (forgetting `subscribeCrossTab` breaks cross-tab sync, forgetting `applyStoredOrSystem` before `applyStoredOrDefault` causes flash, duplicated picker UI drifts between `StylesPage` and `ThemePage`). For `oxygen-ui-rework` (To Do epic that will replace/extend the current shell), a polished theme helper is a standard expected affordance alongside the current 10-pack system — it is not a bug (so `Normal`, not `Higher`/`High`), but it unblocks consistent theming across the reworked `HolyGrail`/`TopBar`/`SideBar` shells which use `S.color.*` vars. Similar `Normal` siblings: OXY-145 resizable panels, OXY-151 mobile/desktop, OXY-152 TopBar dropdown.

**Inferred acceptance criteria:**

1. A single import covers the 4-line bootstrap: e.g. `import oxygen.ui.web.service.ColorTheme` or `Theme.install` such that `override def prePageLoad = ColorTheme.install` (or `Theme.install *> ColorMode.install` combinator) is equivalent to the current 4-line snippet, with correct ordering (CSS sheets already added before `prePageLoad` in `PageApp.scala:79-85` so vars win) and `Scope`-owned cross-tab subscriptions. Existing manual snippet still works (no breaking change).
2. A reusable widget/helper for color mode toggle: e.g. `ColorModePicker` / `ThemeToggle` in `component` — renders Light/Dark/System (segmented control or 3 buttons), calls `ColorMode.setAndPersist`, reflects current `Mode` (`State` or derived from `ColorMode.current`-style read), no caller boilerplate beyond `ColorModePicker()` or `ColorModePicker.compact`.
3. A reusable widget/helper for theme pack selection: e.g. `ThemePicker` / `ThemePackPicker` — renders `OxygenThemes.all` (or filtered) with swatches + name/blurb + selected state, calls `Theme.applyAndPersist`, optionally re-renders page via `PageManager.reRenderCurrentPage` (already done by `Theme.applyAndPersist`), and updates its own `State` (selected `id`). Should compose with the mode picker or be combinable (`ColorThemePicker` that shows both).
4. No new storage keys or pack definitions — reuses `OxygenThemes.*`, `ColorMode.*`, `Theme.*`, `Broadcast.*` channels (`oxygen.color-mode`, `oxygen.theme-pack`). Pack list remains 10; helper supports `filtered: Seq[Pack]` or `exclude: Set[String]` for apps that only expose Graphite family.
5. Styling uses existing `S.color.*` / `S.spacing.*` tokens only — no hard-coded greys, no new CSS vars beyond optional picker-specific sheet (if needed, registered via `coreOxygenStyleSheets` pattern). Accessibility: picker buttons have `aria-pressed` / `role="radiogroup"` style semantics.
6. Showcase/demo: `ThemePage` refactored to use the helper (or a new helper demo page), `StylesPage.colorModeToggle` replaced or documented as delegating to helper, no visual regression for existing `Theme.applyPack` callers.
7. Docs: short section in `docs/docs/ui/builders.md` Theme + color mode (currently `builders.md:187-196`) updated to show the helper as preferred, with manual 4-line form as fallback; `docs/docs/ui/index.md` quick-start updated similarly.

## Open Questions

1. **Facade location & name:** Should the bootstrap helper be `service.ColorTheme.install`, `service.Theme.install`, `service.ThemeHelper.install`, or `defaults.ColorThemeHelper`? `service.ColorTheme` (facade over `ColorMode` + `Theme`) is the cleanest one-import story; `service.Theme.install` is less new surface but still needs `ColorMode`. Which does the rework epic prefer?
2. **Picker State ownership:** Should `ThemePicker` be `PWidget.Deferred.Stateful` with `State(activeId: String)` loaded via `Theme.currentId` (like `ThemePage.PageState`) or stateless (`onClick` only, caller owns `State` via `WidgetState`)? Stateful is zero boilerplate for showcase; stateless is more flexible for apps that persist selection elsewhere (e.g., via `OXY-143` config service).
3. **Mode picker shape:** Segmented 3-button group (`Button.small` with `primary` active) like today, `HorizontalRadio` (choice component), or a `<select>`/`Dropdown`? Current duplication uses buttons; `HorizontalRadio` would be more a11y-correct (`role=radiogroup`) but adds component coupling.
4. **Pack picker shape:** Cards (current `ThemePage` column of bordered cards with swatches) vs `Dropdown` compact vs grid? Cards are demo-friendly; dropdown is better for `TopBar`/`SideBar` density. Should v1 ship one variant or both (`ThemePicker.cards` vs `ThemePicker.dropdown`)?
5. **Pack filter:** Should `ThemePicker` default to `OxygenThemes.all` (10) or `graphiteFamilyPacks` (6 Graphite colorways) with `includeSurfaces: Boolean` opt-in for Aurora/Ember/Violet/Ocean? ThemePage note says "zinc Graphite core + colorways ... plus surface personalities" — filter matters for app defaults.
6. **Cross-tab State sync:** Should pickers subscribe to `Broadcast.subscribeThemePack` / `subscribeThemeMode` to re-highlight when another tab changes theme, or is `subscribeCrossTab` in `prePageLoad` sufficient (it applies CSS but not picker `State`)? If pickers are `Stateful`, they may need their own `subscribe` to update `activeId`.
7. **Persistence layer:** Continue `localStorage` (`oxygen.theme-pack` / `oxygen.color-mode`) or later delegate to `OXY-143` config files service? This Task should keep `localStorage` and note `OXY-143` as follow-up, but confirm.
8. **Coordination with siblings:** Does this Task depend on or overlap OXY-151 (mobile vs desktop — picker responsive layout), OXY-152 (TopBar dropdown — picker could use dropdown for compact), or `htmlAttrs.scala:55` SVG color helpers (unrelated)? Any required ordering within `oxygen-ui-rework`?
