## Expanded Description

**What this task likely is:** Add first-class dropdown / popup-menu support to `TopBar` so an app can declare hierarchical nav or action menus without hand-rolling overlay + click-outside + keyboard logic — e.g., `TopBar.empty.left(TopBar.item("Products").dropdown(TopBar.dropdownItem("All"), TopBar.dropdownItem("Pricing").onClickPush(...)))` where hovering or clicking a `TopBar.Item` opens a positioned menu panel, analogous to a desktop app menubar or GitHub-style nav dropdown.

**Current state (verified from code):**

- `TopBar` (`modules/ui/web/src/main/scala/oxygen/ui/web/component/TopBar.scala:21-242`) is a `PWidget.Deferred` with `Cache(bg,itemHover,itemActive,itemFg,height)` + two `Seq[Item]` slots (`_left`/`_right` via `left`/`right`/`leftItems`/`rightItems`/`leftOpt`/`rightOpt` at lines 67-95). `Item` (`TopBar.scala:138-187`) is `PWidget.Deferred` wrapping a `Growable[Widget]` rendered via `itemWidget` (`224-241`: `inlineFlex center 0 1rem`, `hover`/`hoverActive` via `Cache`). Items support `withIcon`, `onClickPush`/`onClickReplace`, `index`, and arbitrary child `Widget`s via `apply(Widget*)` — but there is no submenu, no `dropdown`/`menu` method, no popup/panel, no `expanded` state, no outside-click handler, and no `DropdownMenu` type on `Item`.
- `build` (`97-128`) renders `bar(leftShrink, growSection, rightShrink)` with `_left.map(_.withBarColors(c))` / `_right` — flat row, no overlay layer. `Cache.default` is `primary.standard/hover/active/on` at `210-218`.
- `Dropdown` (`modules/ui/web/src/main/scala/oxygen/ui/web/component/Dropdown.scala:9-250`) exists but is a **form select** (`Dropdown.State[S](options,selected,expanded)`, `closeOnMouseLeave`, `width/maxDropdownHeight`) — not a nav menu. It is choice-shaped (`Option[A]` selected), not action-shaped (`Seq[MenuAction]`), and lives in form context (`Dropdown.form`, `PForm`). No code reuses it for `TopBar`.
- `component/package.scala:6-8` lists `// TODO : - ContextMenu : - DropdownMenu` — both are explicitly planned but unimplemented types in `oxygen.ui.web.component`. This is the only TODO set that names the missing menu primitive relevant to this Task.
- `Modal` (`component/Modal.scala`) is the only overlay with outside-click + focus management (via `O.ModalOverlay`), but it is a centered dialog, not an anchored popup. `Drawer` (`component/Drawer.scala:12-75`) is a `320px` side overlay with `State(open:Boolean)` + scrim + `onClick := st.update(_.hide)` — the nearest pattern for open/close state, but positioned as a side sheet, not an anchored dropdown.
- Grep across `modules/ui/web/src/main/scala/oxygen/ui/web/` for `Menu|Popover|Overlay|dropdown|DropdownMenu|ContextMenu` (outside `Dropdown.scala` and `Modal`) returns only the `package.scala` TODOs; no `TopBar` dropdown helper, no `MenuItem`, no `Popup` component exists.
- Docs (`docs/docs/ui/builders.md:86-106`, `docs/docs/ui/index.md:29`, `agent-guide.md`) describe `TopBar` as `left/right` `Item` chrome with tokens, `HolyGrail.top(TopBar…)` composition, and list `Button/TextField/Modal/TopBar/SideBar/Drawer` as chrome — no dropdown menu is documented.
- Call sites (`example/apps/ui/src/main/scala/oxygen/example/ui/common/common.scala:9-36`, `showcase/ShowcaseLayout.scala:30-42`) use `TopBar.empty.leftItems/rightItems` with flat `_(\"label\").onClickPush(...)` only — no submenu is attempted, confirming the gap is net-new, not a regression.
- `OxygenStyleSheet` (`create/OxygenStyleSheet.scala:261-340`) has `ModalOverlay`, `Dropdown`, `Button`, `ToggleThumb`, `Table`, etc., but no `TopBarDropdown` / `DropdownMenu` style class — CSS for an anchored panel will be net-new.

**Why it matters (Priority Normal):** `TopBar` is the primary app chrome (every Oxygen app mounts one under `HolyGrail.top`). Today a top bar can only show a flat row of items; any hierarchy ( `Products ▾ -> Pricing | Features`, user avatar -> `Profile | Sign out`, `More ▾` overflow on mobile in OXY-151) must be hand-rolled per app with `Widget.state[Boolean]` + positioned `div` + click-outside + `Escape` + focus restoration — easy to get wrong for a11y. For `oxygen-ui-rework` (the To Do epic that will replace/extend the current chrome), an official dropdown menu is table-stakes for a production shell (akin to Radix `NavigationMenu` / `DropdownMenu`). `Normal` (not `Higher`/`Highest`) signals a feature gap / polish, not a bug or blocker — consistent with being one of several rework subtasks alongside OXY-151 mobile/desktop, OXY-145 resizable panels, OXY-154 color helper.

**Inferred acceptance criteria:**

1. A `TopBar.Item` can declare a dropdown: `TopBar.item("Products").dropdown(items*)` or `TopBar.item.dropdown(label, items*)` where each dropdown entry is a new `TopBar.DropdownItem` / `TopBar.MenuItem` with at least `label: String`, optional `icon: Icon`, `onClickPush(Navigate)`, `onClick: UIO[Unit]`/`onClickAction`, `disabled: Boolean`, `divider`/`separator`, and possibly `action: Action` (like `Button.form` action wiring). Dropdown supports 1 level (flat list) for v1; nested submenus are likely out of scope but should not be foreclosed by the API.
2. Interaction: click on the trigger toggles the panel; hover-to-open is optional but common for desktop menubars — pick one and document. Panel closes on outside-click, on `Escape`, on item selection (unless item opts to keep open), and optionally on `closeOnMouseLeave` (like `Dropdown.closeOnMouseLeave`). Focus: trigger is focusable, `ArrowDown` opens, `ArrowUp/Down` moves, `Enter` selects, `Escape` closes and restores focus to trigger.
3. Positioning: panel is anchored below the trigger, left-aligned by default, `position.absolute` inside a `position.relative` trigger wrapper, `zIndex` above `TopBar` (`ZIndices.modalBehindPageMessages` or a new `ZIndices.dropdown = 500`-ish), `minWidth` at least trigger width, `maxHeight` with `overflowY.auto`. No viewport overflow after open (flip if near edge is nice-to-have, not required for v1).
4. Styling: dropdown panel uses theme tokens (`S.color.bg.layerOne`, `S.color.fg.default`, `S.color.bg.layerTwo` hover, `S.borderRadius._3/_4`, `S.spacing._1/_2` padding, `boxShadow 0 4px 16px rgba(...)`), consistent with `Dropdown.scala` and `SideBar`/`Button` chrome. Shares a `sheet` (`TopBar.Dropdown.sheet` or `O.TopBarDropdown`) registered in `coreOxygenStyleSheets`.
5. API remains builder/immutable: `TopBar.Item` stays `PWidget.Deferred`, dropdown is an immutable config on the item, not a separate stateful widget the caller must manage. Per-dropdown `State(open:Boolean)` is owned internally via `Widget.state` (like `Drawer` at `Drawer.scala:29` `Widget.state[State].fix`), not exposed unless the caller needs controlled mode.
6. No regression for flat callers: `TopBar.empty.left(TopBar.item("Home").onClickPush(...))` and existing `common.scala` / `ShowcaseLayout` call sites render identically with no dropdown overhead.
7. Showcase/demo: `ShellPage` or new `TopBarPage` / `TopBarDropdownPage` demonstrates at least 2 left dropdowns + 1 right dropdown (user menu), including disabled item + separator, and verifies keyboard + outside-click behavior. Docs add a short `TopBar dropdown` snippet in `builders.md`/`agent-guide.md`.
8. Possibly out of scope but to decide: mobile reuse — whether the same dropdown collapses to a `Drawer` on narrow viewports (belongs to OXY-151) or stays as a dropdown on mobile. Coordination note: OXY-151's hamburger vs. `TopBar` overflow `More` menu likely wants the same dropdown component, so the panel primitive should be reusable outside `TopBar` (i.e., `component/DropdownMenu` or `component/ContextMenu`) rather than `TopBar`-only.

## Open Questions

1. **Trigger mode — click vs hover:** Should the dropdown open on `click` (stable, works on touch) or `hover` (menubar feel) or both (`mouseEnter` opens, `click` also toggles)? `Dropdown.scala:closeOnMouseLeave` precedent suggests mouse-leave auto-close was considered for form selects — should this menu follow that pattern or require explicit outside-click/`Escape`? Should `TopBar.Item.dropdown(_.hoverOpen)` be configurable?
2. **Menu-item model shape:** Should items be a new typed `TopBar.DropdownItem` / `TopBar.MenuItem` (label+icon+onClick+disabled+separator, strongly typed) or arbitrary `Widget`s (`withDropdown(Widget)` passthrough)? Should items support `onClickPush(Navigate)` vs `onClick(UIO[Unit])` vs full `Action` param (like `Button.form`)? Should `separator`/`divider` be a distinct item kind or a prop on an item?
3. **Reusable component vs TopBar-only:** Should the panel be a private `TopBar.DropdownPanel` or a standalone `component/DropdownMenu` (or `component/ContextMenu`) reusable by `SideBar` / OXY-151 mobile overflow `More` menu? `package.scala:8` TODO lists `DropdownMenu` separately — does this Task deliver that component or only `TopBar`-scoped dropdown?
4. **Nesting / hierarchy:** Is one flat level sufficient for v1, or must dropdowns support nested submenus (second-level flyout on hover) in the same issue? Title says `dropdown menu` singular — but top bars sometimes need `Products → Features → Subfeature` hierarchy; should nested be deferred to a follow-up?
5. **Keyboard + a11y contract:** Required a11y shape: `role="menu"` + `role="menuitem"` + `aria-haspopup`/`aria-expanded` on trigger + roving `tabIndex` vs simple `tabIndex=0` on each item? Should `ArrowUp/Down` cycle, `Home/End` to edges, `Enter` selects, `Escape` closes and returns focus to trigger? Is a focus trap / `aria-live` needed before landing?
6. **Positioning + overflow:** Is `position.absolute` inside a `position.relative` trigger wrapper sufficient, or is a portal / `fixed` with JS measurement required to avoid `overflow.hidden` clipping from `HolyGrail` (`minHeight:0, overflow.hidden` at `HolyGrail.scala:48`)? Should the panel flip (left→right) when near viewport edge, or is overflow acceptable for v1? What `zIndex` (reuses `ZIndices.modalBehindPageMessages` vs new `ZIndices.dropdown`)?
7. **Coordination with siblings:** Should this Task share the panel primitive with OXY-151 `mobile vs desktop` overflow `More` menu (same component, different trigger), and does ordering matter — should OXY-151 land before or after OXY-152 so the overflow menu reuses this dropdown? Should the caret indicator (`Icon.chevronDown`) be auto-shown when a dropdown is present?
8. **Docs & showcase location:** New `TopBarPage` / `DropdownMenuPage` vs extending `ShellPage`? Include a right-aligned user-menu dropdown example (avatar + `Profile | Sign out`)? Document hover vs click choice and that form `Dropdown` (`Dropdown.scala`) is a different component for choice, not nav?
