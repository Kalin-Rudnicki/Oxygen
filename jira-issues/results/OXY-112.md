## Expanded Description

**What this likely is:** Add a small, reusable helper for **HTTP Basic Authentication** (RFC 7617 — `Authorization: Basic <credentials>` where `credentials = base64(username ":" password)`) that today has **zero support** in the repo and must be built by hand each time with `Header.Authorization`, manual `Base64` and string splitting.

Today the repo has first-class helpers for `Bearer` auth only:

- `modules/crypto/model/src/main/scala/oxygen/crypto/model/BearerToken.scala:14-78` — `BearerToken` case class, `decodeBearer`/`decodeToken`, `bearerStringCodec`/`tokenStringCodec`, `bearerReg = "^Bearer ..."` and `Header.Authorization.Bearer(token)` usage in `modules/http/zio/.jvm/src/main/scala/oxygen/http/server/mcp/UserInfoService.scala:29` and `modules/oidc/src/main/scala/oxygen/oidc/OidcClient.scala:178` (`addHeader("Authorization", s"Bearer $t")`).
- `modules/general/schema/src/main/scala/oxygen/schema/PlainTextSchema.scala:65` — `given bearerToken: PlainTextSchema[BearerToken]` (`BearerTokenSchema`) wired into `RequestCodec.header` for typed header params.
- `modules/crypto/model/src/main/scala/oxygen/crypto/model/Password.scala` — `Password.PlainText`/`Hashed` opaque types with `StringCodec`.
- `modules/crypto/model/src/main/scala/oxygen/crypto/model/Base64.scala` — `stdEncoder`/`stdDecoder` (RFC 4648 standard Base64, not URL-safe) — exactly what RFC 7617 requires.

There is **no `Basic` / `BasicAuth` / `BasicCredentials` type**, no `Basic` header codec, no `Authorization: Basic` middleware, and grep for `Basic` in `modules/crypto` and `modules/http` only hits `Event.Basic`, `Table.basic`, `SideBar.basicItem`, `LineStream.succeedBasic` — all false positives — plus `Base64` type names. `grep -R "BasicAuth\|basicAuth\|Authorization.*Basic"` is empty.

The intended helper is therefore a thin, correctly-specified RFC 7617 utility plus ergonomic integration into `oxygen-http`. At minimum:

1. **Model/codec:** `BasicCredentials(username: String, password: String)` in `modules/crypto/model` (or `modules/http/model`) with `encode: String = "Basic " + Base64.stdEncoder.encodeToString(s"$username:$password".getBytes(UTF_8))` and `decode(headerValue: String): Either[String, BasicCredentials]` that strips the `Basic ` prefix (case-insensitive, trims whitespace), standard-Base64 decodes, splits on the *first* `:` (username may not contain `:` per RFC 7617 §2, password may), validates UTF-8 and that the decoded string contains a colon, and returns typed credentials. Provide `StringCodec[BasicCredentials]` and `PlainTextSchema[BasicCredentials]` analogous to `BearerToken` so it can be used as a typed header param (`RequestCodec.header.plain.required[BasicCredentials]("Authorization")`).

2. **HTTP integration:**
   - Server side: a cheap guard `BasicAuthService` / `RequestCodec` helper or `RequestMiddleware` that validates `Authorization: Basic` against a supplied password hash (via `PasswordService`) or a static `Map[username, Hashed]` / callback `String => Option[Hashed]`, and on failure returns `401` with `WWW-Authenticate: Basic realm="..."` (mirroring `McpEndpointMiddleware.scala:62` which already emits `WWW-Authenticate: Bearer ...` for bearer failures). The `Unauthorized` → `WWW-Authenticate` pattern already exists — reuse it for `Basic`.
   - Client side: `RequestMiddleware.basicAuth(username, password)` (effectless, like `OidcClient.bearerMiddleware:179`) that adds `Authorization: Basic <encoded>` to outgoing `Request`, and `Client.Config` or `ZioHttpClient` helper to attach it. Similar to `OidcClient.bearerMiddleware`, prefer a `RequestMiddleware.Effectless` that calls `request.addHeader("Authorization", credentials.encoded)` or `Header.Authorization.Basic(...)` if zio-http exposes it, otherwise `Header.Custom`.

3. **Edge handling (RFC 7617 + security):**
   - Reject non-Basic schemes, empty value, malformed Base64, missing `:` after decode, empty username, charset issues (RFC 7617 §2.1 — `charset` param, default UTF-8 per RFC 7617, `UTF-8` vs `ISO-8859-1` note).
   - Null/empty password allowed (RFC allows `username:` with empty password).
   - Redaction: `Show[BasicCredentials]` must redact password (like `Password.PlainText` display `***`) and error messages must not leak it; `HttpDecodingFailure.authNames` already treats `password`/`auth`/`token` as sensitive.
   - Logging: do not log the header value verbatim.

**Who it affects:** Any service that must (a) call a legacy / third-party endpoint protected by Basic auth (outgoing client), (b) expose an endpoint behind Basic auth (e.g. health check, webhook, admin, or a simple internal service where JWT/OIDC is overkill), or (c) need to interop with `curl -u user:pass` / `Authorization: Basic ...` in tests. Today every such call does ad-hoc `Base64.getEncoder.encodeToString(s"$u:$p".getBytes)` + `addHeader("Authorization", s"Basic $b64")` with inconsistent `Basic ` prefix handling, charset choice, and no `PlainTextSchema` so it cannot be a typed `RequestCodec.header` param.

**Why it matters (Priority Low):** Bearer/JWT/OIDC (`BearerToken`, `JWT`, `OidcClient`, `McpAuthService`) are the primary auth story for `oxygen-http`; Basic auth is legacy, weaker (credentials sent per-request, no expiry), and not needed for the main OIDC/MCP flows. Priority `Low` (vs OXY-17 High `IN`, OXY-55 High performance framework) reflects that it is completeness/ergonomics, not a blocker. Still, the lack of a helper is a paper-cut: the `Base64` codec exists, the `Authorization` header pattern exists, and the `Password` type exists — a helper removes duplicated, subtly-incorrect hand-rolled encoders (e.g. using URL-safe Base64, forgetting the `Basic ` prefix, splitting on last `:` instead of first, or leaking passwords in logs).

**Inferred acceptance criteria:**

1. `BasicCredentials` (or `BasicAuth`) model in `modules/crypto/model` (or `modules/http/model`) with `username: String`, `password` (likely `Password.PlainText` or `String` with redacted `Show`), methods `encoded: String` (`"Basic <b64>"`) and `decodedHeader: String`, companion `decode(headerValue: String): Either[String, BasicCredentials]` / `fromHeader(header: String): Either[String, BasicCredentials]` implementing RFC 7617 exactly, plus `StringCodec[BasicCredentials]` (and `PlainTextSchema[BasicCredentials]`) so it works as `RequestCodec.header.plain.required[BasicCredentials]("Authorization")` or `RequestCodec.header.fromPartial(...)`.

2. Server helper that can be used as a `RequestCodec` or middleware: e.g. `BasicAuth.validate(credentials: BasicCredentials, lookup: String => Option[Password.Hashed]): IO[Unit]` or `BasicAuthService` with `authenticate(credentials) -> IO[AuthError, Unit]`, and a `RequestMiddleware` or `Server` plug that on failure returns `401 Unauthorized` with `WWW-Authenticate: Basic realm="<realm>"` (realm configurable, default `"oxygen"` or `"Restricted"` per RFC 7617 §2).

3. Client helper: `RequestMiddleware.basicAuth(username: String, password: String)` / `RequestMiddleware.basicAuth(credentials: BasicCredentials)` or `BasicCredentials.toRequestMiddleware` / extension `request.withBasicAuth(...)` that adds `Authorization: Basic ...` — effectless, composable via `>>>` like other `RequestMiddleware.Effectless`.

4. Round-trip property: `decode(encode(creds)) == Right(creds)` for arbitrary `username` (no `:`) and `password` (any string including `:` and empty), plus negative tests: missing `Basic ` prefix → `Left`, wrong scheme `Bearer ...` → `Left`, invalid Base64 → `Left`, decoded value without `:` → `Left`, whitespace handling (`"  Basic  <b64>  "`).

5. Tests + docs: unit tests in `modules/crypto/service/src/test` or `modules/http/zio/src/test` covering RFC 7617 examples (`Aladdin:open sesame` → `QWxhZGRpbjpvcGVuIHNlc2FtZQ==`), edge cases above, and redaction of `Show`; integration test via `ViaHttpSpec`/`DirectSpec` showing typed header `BasicCredentials` round-trips through `RequestCodec` and that a protected endpoint returns `401` without credentials and `200` with valid ones. Minimal doc in `docs/docs/http` or `modules/crypto/README` noting `Basic` vs `Bearer` when to use which, and a note that Basic should only be used over HTTPS (like `OXY-80 easy HTTPS config to client`).

## Open Questions

1. **Owning module & type name:** Should the canonical type live in `modules/crypto/model` (`oxygen.crypto.model.BasicCredentials` alongside `BearerToken` + `Password`) or in `modules/http/model` / `modules/http/zio/src/main/scala/oxygen/http/model` (`oxygen.http.model.BasicAuth`)? Checklist adjacency says `OXY-111 oxygen-crypto` but `Authorization: Basic` is an HTTP concept. Which module should own the `StringCodec`/`PlainTextSchema` — or should it be duplicated with a type alias? Proposed: `crypto/model` owns `BasicCredentials` with `StringCodec`, `http/zio` re-exports or adds `RequestMiddleware.basicAuth` + `PlainTextSchema` given in `schema`.

2. **Password field type:** `username: String` is clear, but should `password` be `String`, `Password.PlainText` (opaque `String` with redacted `Show` in `Password.scala:10`), or `Bytes.Raw`? `Password.PlainText` gives `Show` redaction for free and signals "must not be logged", but adds a `.unsafeGetRawPassword` call at encode time. `String` is simpler. Which is preferred, and should `Show[BasicCredentials]` redact via `Password`'s `Show` or custom `***`?

3. **`BasicAuthService` in scope?** Is the issue just the encode/decode + `RequestMiddleware.basicAuth` helpers (client convenience), or also a server guard that validates `Authorization: Basic` against `PasswordService`/`Password.Hashed` and returns `401 + WWW-Authenticate: Basic realm="..."`? `Low` priority suggests helpers only, but the `WWW-Authenticate: Basic realm` pattern (already in `McpEndpointMiddleware:62` for `Bearer`) is a natural server companion — should it be included or deferred to OXY-116/117 (`real client/server error handlers for provided models`)?

4. **Realm & charset:** What `WWW-Authenticate` `realm` should the server emit (`"oxygen"`, `"Restricted"`, or app-configurable via `BasicAuthConfig(realm: String)`)? RFC 7617 §2 requires `realm` (quoted-string) and suggests `charset="UTF-8"` (IANA `charset` param) for non-ASCII credentials — should the helper emit `WWW-Authenticate: Basic realm="...", charset="UTF-8"` or just `realm`?
