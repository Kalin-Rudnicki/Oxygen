object IndexedDB {

Key design contracts inferred from `LocalStorage` precedent and `IndexedDB.scala` migration shape:
- Typed values via `oxygen-json` `JsonCodec` / `oxygen-schema` `StringCodec` (as `LocalStorage.storageKey.json`/`string` already do), or via `AnySchemaT`/`JsonSchema` as `Broadcast` does — choose one and be consistent.
- ZIO error model via `UIError.ClientSide.InternalDefect` (as `LocalStorage.find.string/json` map decode failures) or a dedicated `IndexedDBError` ADT, not raw `RuntimeException("IndexedDB not available")` (`IndexedDB.scala:58,62`).
- `ZLayer` wiring (`IndexedDB.live: ULayer[IndexedDB]` or `Database` as a scoped resource) similar to `LocalStorage.live` and `Broadcast.make` scoped pattern, so tests can provide an in-memory stub (or skip when `isAvailable == false`).
- Versioned migrations remain `Seq[Migration]` with `StoreSpec(name, keyPath, autoIncrement)`; follow-up must clarify whether indexes, `deleteObjectStore`, and `createIndex` are in scope or deferred (current `onupgradeneeded` only handles `createObjectStore` if absent, not indexes/deletes).
- `IDBRequest`/`IDBTransaction` async bridging via `ZIO.async` (as `open` already does at `IndexedDB.scala:55`), handling `onsuccess`/`onerror`/`onblocked`/`onabort` correctly, and `ZIO.attempt(...).orDie` vs `Task` error channel decision.

**Who it affects:** Any Oxygen UI app that needs durable, structured, offline-capable browser storage beyond the 5-10 MB `localStorage` string limit — e.g., caching `oxygen-http` responses, persisting large form drafts, offline queues, or `PageLocalState`/`GlobalState` hydration. Today those apps either use `LocalStorage` (string/JSON in `localStorage` via `ColorMode.storageKey`/`Theme.storageKey` at `ColorMode.scala:45,64,69` and `Theme.scala:19,48,53` — both hit `window.localStorage` directly rather than via the `LocalStorage` trait) or fall through to `unsafeRaw` and hand-roll `IDBTransaction.objectStore(...).get/put/delete` with raw `js.Dynamic` casts.

**Why it matters (Priority Normal, not High/Higher):** `Normal` (not `High` like OXY-17 IN support, nor `Higher` like OXY-143 config service) signals this is a completion / DX consolidation task, not a blocking precursor. The `oxygen-ui` rework can ship with the minimal `open` helper; apps can still reach storage via `unsafeRaw`. "Actually implement" is therefore polish that removes the `unsafeRaw` escape hatch and gives teams the same typed ergonomics `LocalStorage` already provides — consistent with the `Low`/`Normal` band of sibling `service` helpers (`MatchMedia`, `Intersect`, `HashScroll`, `Window` are all small `object`s with 1-3 methods).
