## Expanded Description

**What this task likely is:** Add first-class primitives so Oxygen UI apps can render different chrome and layout per form-factor — i.e., let a single `HolyGrail`-based app show a desktop chrome (persistent left `SideBar`, hover `TopBar` items, wide `CenteredCard`) on `>= md` and a mobile chrome (hidden rails → hamburger/drawer, stacked `Row/Col`, full-width cards, larger tap targets) on `< md`, without each team hand-rolling `window.matchMedia` or CSS hacks.

**Current state (verified from code):**

- `HolyGrail` (`modules/ui/web/src/main/scala/oxygen/ui/web/layout/HolyGrail.scala:7-350`) has exactly one responsive behavior: `HolyGrail.responsiveSheet` (`HolyGrail.scala:310-348`) via `MediaCSS.belowMd` collapses the shell to `grid-template-columns: 1fr` / `"top-bar" "center" "bottom-bar"` and `display: none` on `.oxy-holy-grail-left/right`. Comment at `HolyGrail.scala:305` says `Drawer/hamburger = Round 2 / TopBar todo` — the mobile nav replacement is explicitly deferred.
- `CenteredCard` (`modules/ui/web/src/main/scala/oxygen/ui/web/layout/CenteredCard.scala:6`) has `// TODO (KR) : this probably needs some mobile awareness...` — no responsive variant exists.
- `Breakpoints` (`modules/ui/web/src/main/scala/oxygen/ui/web/style/Breakpoints.scala:7-38`) defines `xs 0, sm 480, md 768, lg 1024, xl 1280` plus `belowMd` helper. `MediaCSS` (`modules/ui/web/src/main/scala/oxygen/ui/web/create/MediaCSS.scala:9-31`) exposes `belowMd/mdUp/lgUp/smUp/xlUp` + `block`. `Row/Col` (`modules/ui/web/src/main/scala/oxygen/ui/web/component/columns.scala:6-101`) is the only existing mobile-aware layout primitive — mobile-first `xs` base plus breakpoint overrides (`oxy-col-sm` etc.). No other component consumes `Breakpoints` directly.
- `MatchMedia` (`modules/ui/web/src/main/scala/oxygen/ui/web/service/MatchMedia.scala:9-53`) exists but only exposes `prefersDark`, `prefersReducedMotion`, `minWidth/maxWidth`, `matches` and `onChange(query)(Boolean => Unit)` — no `isMobile`, no `isBelowMd` helper, no `Widget`-level conditional, no hook tied to `Breakpoints.md`. `Window` (`modules/ui/web/src/main/scala/oxygen/ui/web/service/Window.scala`) has no mobile/desktop helpers.
- `TopBar` (`modules/ui/web/src/main/scala/oxygen/ui/web/component/TopBar.scala:21-242`) has no hamburger, no overflow menu, no `Drawer` integration. `Drawer` (`modules/ui/web/src/main/scala/oxygen/ui/web/component/Drawer.scala:8-75`) is a standalone overlay (`Side.Left/Right`, `320px` panelWidth) with `State(open:Boolean)` — not wired to `HolyGrail` or `TopBar`, and still `TODO eventually follow PWidget.Deferred`.
- `NavBar` (`modules/ui/web/src/main/scala/oxygen/ui/web/component/NavBar.scala:38`) TODO notes `this will be helpful for being able to display things differently on web/mobile` — explicitly calls out web vs mobile divergent rendering, not yet implemented.
- Docs (`docs/docs/ui/builders.md:199-204`, `docs/docs/ui/index.md`, `docs/docs/ui/agent-guide.md:63`) state: `PageApp` injects `width=device-width` viewport meta (`PageApp.scala:35-46` does `ensureViewportMeta`), server HTML includes same meta (`build.sbt:1053`), `maxWidth 100% + borderBox` is recommended, and `Known gaps` lists `Mobile shell: Viewport meta helps a lot; narrow layouts still rough` (`builders.md:225`). All confirm mobile support is acknowledged as incomplete and intentionally deferred to this Task's generation of work (OXY-133 rework cluster).
- No `isMobile`, `useBreakpoint`, `Responsive`, `MobileOnly`/`DesktopOnly`, `useMediaQuery`, or `ShowOn` widget was found by grepping `modules/ui/web/src/main/scala/oxygen/ui/web/` for `mobile/Mobile/isMobile/breakpoint/Breakpoint/Responsive/desktop/Desktop/hamburger` (only hits are `CenteredCard` TODO, `HolyGrail` Round-2 comment, `NavBar` TODO, `Breakpoints/MediaCSS/columns` infra).

**Why it matters (Priority Normal):** Without this, every Oxygen app either ships a desktop-only shell that breaks on phones (fixed `250px` rails overflow, `TopBar` items wrap, `CenteredCard` wastes gutters) or forks two nav trees manually. For `oxygen-ui-rework` (the To Do epic that will replace the current shells), mobile/desktop divergence is a prerequisite to `oxygen-ui` feeling production-ready. `Normal` (not `Higher`/`Highest`) signals a feature gap / polish, not a bug or blocker — consistent with being one of several rework subtasks alongside OXY-145 resizable panels, OXY-152 TopBar dropdown, OXY-154 color helper.

**Inferred acceptance criteria:**

1. A desktop layout (`>= md` ~768px) keeps the current `HolyGrail` chrome: `TopBar` with visible left/right items, persistent `SideBar` left/right rails, center `1fr`, `ColumnsStyle` grid as today. No regression for existing `HolyGrail.empty.top(...).modLeft(...).center(...)` callers.
2. A mobile layout (`< md`) provides a distinct chrome: left/right rails hidden (existing `responsiveSheet` behavior retained), `TopBar` shows a hamburger button that opens the left nav in a `Drawer` (or bottom sheet) overlay, and body content stacks via `Row/Col` single column (12-span). Tap targets meet `>= 44px` / existing `min-height: 52px` on `.oxy-holy-grail-top` in the responsive sheet.
3. Developers can branch per-breakpoint either declaratively in CSS (media helpers) or imperatively in widgets: a `Widget.when(isMobile)` or `Responsive { isMobile => ... }` / `MediaQuery` helper that subscribes to `matchMedia` and re-renders on change, without leaking `window` access to SSR (guard `dom.window` absence).
4. Optional but likely expected: `CenteredCard` becomes mobile-aware (full-width on narrow, gutters collapse), `TopBar` gains an overflow pattern (priority+ `More` dropdown or hamburger) so many nav items don't overflow on narrow, and `ShowcaseLayout` / `ShellPage` demo both form factors (resize viewport or toggle).
5. No new viewport meta needed (already injected); work builds on existing `Breakpoints` + `MediaCSS` + `MatchMedia` infra — not a new breakpoint scale.
6. Showcase/demo: existing `ShellPage` (`example/apps/ui/src/main/scala/oxygen/example/ui/page/showcase/pages/ShellPage.scala:14` `Resize viewport for responsive collapse.`) extended or a new `ResponsivePage` shows hamburger drawer vs persistent rail, `GridPage` already demonstrates `Row/Col` reflow.

## Open Questions

1. **Scope — which patterns?** Should v1 deliver (a) hamburger → `Drawer` for `HolyGrail` left nav only, (b) that plus `TopBar` overflow/`More` dropdown on narrow, or (c) also `CenteredCard` mobile gutters and `Row/Col` helpers? Title says "mobile vs desktop differences" plural — suggests at least two surfaces.
2. **State ownership:** Should `HolyGrail` own the mobile drawer `State` (zero boilerplate, opinionated) or should it be page-owned (`Widget.state[Drawer.State]` per page, less magic)? `DrawerPage` precedent is page-owned; `HolyGrail` `pageMessagesSlot` precedent is shell-owned — which direction does the rework prefer?
3. **Responsive primitive shape:** CSS-only `MediaCSS.hideBelowMd` classes (no JS, no SSR risk) vs `Widget.mediaQuery` subscription via `MatchMedia.onChange` (js re-render on resize, SSR guard needed) vs both? Should the helper live in `create.MediaCSS`, `service.MatchMedia`, or a new `component.Responsive` widget?
4. **Breakpoint choice:** Is `md = 768px` the correct mobile/desktop cutoff for the shell (already used by `responsiveSheet`), or should hamburger appear at `lg = 1024px` for tablet? Should it be configurable per-app (`.mobileBreakpoint(Int)`) or fixed?
5. **Drawer vs bottom sheet:** On phones, should left nav appear as a side `Drawer` (left 280px) or a full-width bottom sheet? Side drawer matches `Drawer` today; bottom sheet would need a new variant. Any required focus trap / a11y before landing?
6. **SSR / hydration:** `window.matchMedia` is absent during SSR (`PageHtmlResponse`/`PageApp` server render). Should mobile check default to desktop on server and hydrate to correct on client, or ship CSS-only first and add JS subscription later to avoid FOUC?
7. **Coordination with siblings:** Does this Task depend on or overlap OXY-152 `TopBar dropdown` (overflow menu), OXY-145 `Resizable panels` (drag vs hamburger interaction below `md`), and OXY-143 `config files` (persist mobile vs desktop preference)? Which epic ordering does the team expect — OXY-151 before or after OXY-152?
8. **Design sign-off:** Confirm tap-target size (currently `min-height 52px` on `.oxy-holy-grail-top` below `md`), drawer width (`320px` today vs `280px` vs `85vw`), scrim darkness (`rgba(0,0,0,0.45)`), and whether `CenteredCard` padding collapse (`1rem`) matches design tokens.
