## Expanded Description

**What this likely is:** Polish and expand the existing `oxygen-sql` user-facing documentation so that a developer can adopt the SQL layer without reading macro-heavy DSL source or `example/` as the only exemplar. Unlike `oxygen-http` (where all three pages under `Oxygen HTTP` in `docs/mkdocs.yml` are 4-line `TODO : Oxygen HTTP*` placeholders — sibling **OXY-81 · High**), `oxygen-sql` already has a substantive doc set:

- `docs/docs/sql/index.md` (76 lines) — overview, quick-start (`@tableName` / `TableCompanion` / `TableRepr.derived`), `ZIO[Database, QueryError, …]` run sketch, layer wiring (`DbConfig` → `Database.layer` → `Atomically`), and mental-model table.
- `docs/docs/sql/models.md` (145 lines) — defining tables, 5 annotations (`@tableName`, `@schemaName`, `@columnName`, `@primaryKey`, `@inlineColumnNames`), `TableCompanion[A,K]` / composite keys / `NoKey`, column types (13 built-ins + `Json`/`Jsonb`/`Vector`/`LTree`), nullability, `RowRepr.transform`, `TypedJsonb`, embedded case classes.
- `docs/docs/sql/queries.md` (156 lines) — `Query`/`QueryI`/`QueryO`/`QueryIO`, generated CRUD (`insert`/`selectAll`/`selectByPK`/`update`/`deleteByPK`/`upsert`/`insertOrDoNothing`/`truncate`/`select_*` + `batchOptimized*`), executing & shaping (`single`/`option`/`to`/`chunk`/`stream`), hand-written DSL via `QueryIO.compile` / `@compile` with `input`/`select`/`join`/`leftJoin`/`where`/`orderBy`/`limit`/`offset`/`Q.insert`/`Q.update`/`Q.delete`.
- `docs/docs/sql/database.md` (118 lines) — `DbConfig` shape + JSON example, `Database.layer` / `healthCheck`, `Atomically` (`LiveDB` vs `RollbackDB`, savepoints), wiring, test isolation (`SqlAspects.isolateTestsInRollbackTransaction`, `PostgresTestContainer`).
- `docs/docs/sql/migrations.md` (136 lines) — filesystem-first workflow, `MigrationSchema.of`, `DbMigrationSpec` guard spec, `OXYGEN_MIGRATION_ALLOW_UPDATE` / `ALLOW_INCOMPATIBLE`, versioning/bump rules, `MigrationService` / `MigrationConfig.Atomicity`, drift errors, local collapse, file format.

Total ~631 lines across 5 pages — the most complete section in `docs/mkdocs.yml` alongside `Oxygen Executable` and `Oxygen UI`. The remaining gap is **coverage and depth**, not scaffolding: recent and in-flight SQL features have no doc surface, and several existing pages are thin on examples, edge cases, and operational guidance.

**Inferred scope (frontrunner):** Bring `docs/docs/sql/*` to parity with the current code surface and with the quality bar set by `docs/docs/sql/index.md` + `docs/docs/executable/index.md`:

1. **Audit and tighten the 5 existing pages** — fix any stale snippets, ensure every code fence compiles against `modules/sql/core` + `modules/sql/storage` + `modules/sql/migration` + `modules/sql/test-utils`, add missing cross-links (`index.md` ↔ sub-pages), and align style (tables, admonitions, `material` theme extensions already enabled in `docs/mkdocs.yml`).
2. **Document the current DSL surface completely** — enumerate every `Q.*` verb, `T.*` type, and `TableCompanion` member that exists today, with minimal copy-pasteable examples. Gaps verified by reading `modules/sql/core/src/main/scala/oxygen/sql/query/dsl/Q.scala` and `TableCompanion.scala`: `select.subQuery`, `insert.fromSelect`, `count.*`/`count._1`, vector/`ltree` operators (`<=>`, `<#>`, `<->`, `<+>`, `@>`, `<@`), `mkSqlString`, `batchOptimizedInsert` chunking, `usingDb` / `Database.withQueryLogLevel`.
3. **Add an "Advanced / upcoming" note** — the To Do list contains several `oxygen-sql` tasks whose *absence* is itself worth documenting so readers don't assume the feature exists: `OXY-6 array input + unnest`, `OXY-13 automatic join clauses`, `OXY-14 querying into a JSONB structure` (beyond current `TypedJsonb` opaque column), `OXY-17 IN support`, `OXY-94 on conflict` (current `upsert` is PK-only), `OXY-97 explicitly naming FK + IDX`, `OXY-98 lateral join + union all + sparse data + zstream agg`, `OXY-100 group by`, `OXY-96 prepared statement caching`, `OXY-123 DB Schema compatibility spec`, `OXY-96/97` etc. Each can be a one-line "Planned — see OXY-#" callout rather than speculative spec, keeping docs honest.
4. **Operational completeness** — expand `database.md`/`migrations.md` with troubleshooting (e.g., `MissingMigration`/`MigrationsDiffer`/`OutOfOrderMigration` recovery), extension setup (`vector`, `ltree` `CREATE EXTENSION` via migrations), and test patterns (parallelism + rollback isolation).

**Who it affects:** Every consumer of `oxygen-sql` — app authors defining tables/queries, service owners wiring `Database`/`Atomically`, and contributors extending the DSL. Unlike HTTP (where missing docs block onboarding), SQL docs are usable today; the pain is "I can't tell if feature X is supported or how to do Y without reading source."
