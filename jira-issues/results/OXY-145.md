## Expanded Description

**What this task likely is:** Make the `oxygen-ui` shell panels user-resizable by dragging dividers — i.e., let a user grab the boundary between `HolyGrail`'s left sidebar / center / right sidebar (and possibly top/bottom) and drag to resize, rather than only using the current fixed imperative `.leftWidth("250px")` / `.rightWidth("250px")` API. Title `Resizable panels` is plural, implying at least two adjustable regions.

**Current state (verified from code):**

- `HolyGrail` (`modules/ui/web/src/main/scala/oxygen/ui/web/layout/HolyGrail.scala:7-350`) is a `PWidget.Deferred` with a `Cache(leftSize: String, rightSize: String, topSize: String, bottomSize: String, showLeft/Right/Top/Bottom: Boolean)` that feeds `gridTemplateColumns` / `gridTemplateRows` via `util.dynamicTemplateSizes`. Sizes are fixed strings set once via `.leftWidth(s)`, `.rightWidth(s)`, `.topHeight(s)`, `.bottomHeight(s)` (`HolyGrail.scala:89-92`). No state, no pointer/mouse handlers, no divider widget, no `onMouseDown` / `onPointerDown`, no `Stateful` — `HolyGrail` is stateless/pure config today.
- `SideBar` (`modules/ui/web/src/main/scala/oxygen/ui/web/component/SideBar.scala:18-110`) is similarly fixed: a grid with `top/middle/bottom` slots, no resizable edge. `Drawer` (`Drawer.scala:12-75`) is an overlay, not a resizable dock.
- Responsive behavior (`HolyGrail.responsiveSheet`, `HolyGrail.scala:320-350`) currently **hides** left/right on `belowMd` (`display: none`) and collapses to `1fr` single column — there is no intermediate draggable breakpoint.
- No `ResizablePanel`, `SplitPane`, `Divider`, or `Gutter` component exists in `modules/ui/web/src/main/scala/oxygen/ui/web/` (grep for `resiz`, `Drag`, `split`, `Divider`, `gutter` finds only `TextArea.resize.vertical`, `DragPresentation`, `SortableList` — none are panel resizers; verified by `grep -r` in Step 3).
- `columns.scala` (`Row`/`Col`) is the only existing layout division logic and is breakpoint-based, not drag-based.
- Docs (`docs/docs/ui/index.md`, `builders.md`, `agent-guide.md`) describe `HolyGrail` / `SideBar` / `CenteredCard` as immutable builder shells with no mention of dragging; no TODO for resizable panels was found.

**Why it matters (Priority Normal):** This is the ergonomic follow-up to `oxygen-ui-rework`. Fixed-width sidebars waste space on wide monitors and starve the center on narrow desktops; a draggable divider lets users allocate space to nav vs content vs inspector per task. For `oxygen-ui-rework` (the To Do epic that will replace/extend the current `oxygen-ui` shells), resizable panels are a standard expected affordance (VS Code-style activity bar + side explorer + editor + right inspector). `Normal` (not `Higher`/`Highest`) suggests it is a feature gap, not a bug or blocker — consistent with being one of several rework subtasks (OXY-151 mobile/desktop, OXY-152 TopBar dropdown, OXY-154 color theme helper).

**Inferred acceptance criteria:**

1. User can drag the vertical divider(s) between `left | center | right` to resize sidebars continuously; drag updates `gridTemplateColumns` in real time, clamped between a configurable `minWidth`/`maxWidth` (e.g., left `180px–480px`, right `200px–500px`, defaults `250px`). Double-click on the divider resets to default.
2. Horizontal variant if `top`/`bottom` panels are shown: draggable horizontal divider resizes `topHeight`/`bottomHeight` with similar clamping.
3. Cursor feedback: `ew-resize` (vertical divider) / `ns-resize` (horizontal), `grabbing` while dragging, 4–8px hit area (wider than visual 1px border) so it is easy to grab on desktop.
4. Panels remain CSS-grid based; resizing modifies only the `Cache` sizes (no DOM restructure). Center stays `1fr` and `minWidth: 0` so it flexes.
5. No resize on touch/mobile while `responsiveSheet` collapses sidebars — dividers hidden when sidebars are hidden (`belowMd` → `display: none`). Optionally collapse sidebar if dragged to `minWidth` threshold (common IDE pattern) — clarify if in scope.
6. State: resizing is per-shell instance, not global. Options: transient drag state (`Widget.Stateful` local `Double` width) vs. `PageLocalState` vs. persisted via `localStorage` / config service (`OXY-143` `config files` service). Persistence is likely desired but not explicit — needs confirmation.
7. Accessibility: divider has `role="separator"` + `aria-orientation="vertical"` + `aria-valuenow/min/max`, keyboard support (`ArrowLeft/Right` adjusts by 10px, `Home/End` to min/max) is expected for a11y but may be follow-up.
8. No visual regression for fixed-width callers: `HolyGrail.empty.leftWidth("300px")` still works with resizable off; resizable is opt-in (`HolyGrail.resizable` or `leftResizable(true)` / `.leftWidth(...).leftResizable(min, max)` chain) or on by default for reworked shell — decision needed.
9. Showcase/demo: a `ShellPage` or new `ResizablePanelsPage` demonstrates left+right drag, shows current widths, works after `responsiveSheet` breakpoint (sidebars hidden → no divider).

## Open Questions

1. **Panel scope:** Which panels should be resizable? Left+right vertical dividers only (most common, plural still satisfied) or also top/bottom horizontal dividers? Should the center be splittable internally (N-way `SplitPane`) or is HolyGrail's outer shell the only surface?
2. **Opt-in vs default-on:** Should `HolyGrail` become resizable by default in the reworked shell, or is it opt-in per call site (`.resizable()` / `.leftResizable(true)`)? Should existing callers with fixed `.leftWidth("220px")` stay fixed unless they opt in?
3. **Persistence:** Should dragged sizes persist across reloads? If so, via `localStorage` key (`oxy:holygrail:leftWidth`) or via `OXY-143`'s config-file service (not yet implemented)? Per-page key vs global key? Debounce interval? If transient only, is that acceptable for rework v1?
4. **Min/max + collapse:** What are the clamp bounds (e.g., left 180–480px, right 200–500px) and defaults? Should dragging to `min` collapse/hide the sidebar (common IDE UX) or stop at `minWidth` and require close button? Should sidebar toggle button snap open to last dragged width?
5. **Divider affordance:** Hit area width (4px vs 6px vs 8px), visual `1px border` vs `2px hover` highlight, hover/active colors (`S.color.primary.subtle`?), double-click to reset — all need design confirmation to avoid follow-up polish churn.
6. **Mobile / responsive interaction:** `responsiveSheet` currently hides sidebars below `md` — should resizers also be hidden there (yes, presumably), or should they become bottom-sheet drawers? Any touch-drag behavior on tablets or is drag desktop-only?
7. **Accessibility:** Are `role="separator"` + `aria-valuenow/min/max` + `tabIndex=0` + keyboard (`ArrowLeft/Right` ±10px, `Home/End`) required for a11y pass, or out of scope for this Task? Must focus remain in center while dragging?
8. **Relation to OXY-143 / OXY-151:** Does this Task depend on `OXY-143` (config files) for persistence, or can it ship independently with `localStorage` and migrate later? Does `OXY-151` (mobile vs desktop) own the responsive collapse that resizers must interop with — any coordination needed?
